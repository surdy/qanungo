# coach

The coaching half of qanungo's report lane (qanungo#4, #7). `qanungo report` computes the *readings* — five practice lanes scored 0–100 per harness from this window's own data, the components that spent each lane's points with their raw fire rates, findings with hash-cited evidence, a Gaps section, and a rule-pack stamp; this skill reads them with the user: what the numbers mean, what to change in how they drive their coding agents, and what not to over-read. qanungo stays deterministic and LLM-free; the coaching happens here, in the harness.

## Steps

**Requires an archive URL.** `PATWARI_URL` must be set in the shell, or `--patwari-url <URL>` passed on each command; there is no default archive. If a command exits 2 with the missing-archive message, stop and tell the user to finish the install as the README's Install section describes.

1. **Run the command.** `qanungo report --last 30d` (that window is the default; take the user's — `h`/`d`/`w` units, no `m` by design). The document is Cadence, Tool use, **Practice scores** (a per-harness plus Fleet table, then "Why the scores are what they are", where fire-rate components read `fired on N of M (X%) — P points off`, the tool-error component reads as a pooled call rate, and a no-reading component says so), **Findings** (one section per rule that fired: **Problem**, **Action**, hash **Evidence**), **Gaps**, and the instrumentation footer carrying the rule-pack hash.
2. **Read the component lines before the score.** A lane is `100 × (1 − mean(reading / floor))` over the components that *read* (each ratio clamped at 1), so the score is downstream of rates printed right beside it. The rate is what moves; the score is a rounded lens over it. Open any "why is my X low" answer with the component that spent the points, in its own numbers — "heavily resumed fired on 27 of 356 sessions (8%), 15 of the 22 points off" — not with the score.
3. **Never read an unscored lane as a bad one.** `no reading` means *could not observe*: a component with fewer than 5 eligible sessions, or a harness whose surface the fold cannot type at all — Copilot's Code Review is the standing case, because its slash commands are unmarked prose, so "Copilot ran no review" is a sentence nothing in the archive can say. No signal, no claim. Name what is missing and why; never average around it, fill it with a proxy, or let it read as a zero.
4. **Say the floor out loud on any 0.** Every fire-rate component saturates at `FIRE_RATE_FLOOR = 0.25`: a rule firing on a quarter or more of its eligible sessions spends its whole share, so the lane reads 0 anywhere from 25% to 100% and will not budge until the rate falls back under a quarter. (As of this writing Code Review sits far above it.) Coaching a 0 lane therefore means coaching **the fire rate**, not the 0 — quote the rate, say what would have to change for it to cross under 25%, and warn that real progress will show as a falling percentage long before the lane number twitches. The floor is a deliberate pack-wide constant; never propose moving it to make a number look better.
5. **Trends are behaviour drift, never rule drift.** Every run recomputes all of history under the *current* pack (qanungo ADR 0001), so an arrow can only mean the behaviour changed. Two reports are comparable **only if their rule-pack stamps match** — check the footer before quoting a delta across runs. Arrows are deliberately suppressed where the comparison window holds no session or the harness roster differs between the two sides; where there is no arrow there is no trend, and the honest answer is "this window has nothing to compare against".
6. **Trace every recommendation.** Each thing you tell the user to change must point at a finding, a score, or a rate in the output; each rule's own **Action** paragraph is the vetted advice and is worth carrying over. Findings cite `sha256:` transcript hashes and aggregates — never a title, a command, an error, or a file — so invent no session detail around one. To see the events behind a finding, the dashboard's evidence view expands it; for "which session was that", `/ask` and `session-recall` are the recall path, and the footer's `GET …/artifacts?original_sha256=<hash>` line is how a hash is redeemed.
7. **Carry the Gaps, and respect the window.** A non-empty Gaps section is archived sessions that contributed nothing to the fold — say so ("1 session had no transcript artifact") rather than coaching around it. The sampling-bias line under the score table is part of the answer too: a harness that contributed no session to the window is described by nothing above it. If the user's question is wider than the window you ran, re-run with a wider `--last` instead of extrapolating.
8. **Be direct, and stop where the data stops.** The user asked to be coached, so do not hedge the findings into nothing — 177 sessions that shipped without a review pass is 177 sessions that shipped without a review pass. But keep "the data shows X" apart from "you should feel Y about it": every threshold in the pack is a constant marked *arbitrary until measured*, a score is a lens rather than a verdict on the work, and a rule that fires constantly is as likely to be a wrong threshold as a bad habit. No moralizing past the numbers.

## Redaction boundary (qanungo#8)

Alone among qanungo's lanes this one has **nothing to redact and no `--no-redact` flag** — `qanungo report --no-redact` is a parse error by design. The report renders aggregates, tool names, and `source_hash` references, and that is a property of *construction* rather than of filtering: nothing in the render path has ever held a transcript string (decision 9's P0 exemption — zero verbatim field content). So this surface cannot leak, and the skill must not try to make it verbatim: do not reconstruct the commands, error text, or prose behind a finding, and do not offer to. Quoting verbatim is the dashboard evidence view's job and `ask --verbatim`'s, both already redaction-gated.

## Boundaries

- Read-only end to end: the command mirrors and folds; nothing writes to the archive, and nothing here edits the user's files — proposing an instruction edit is `instructions-editor`'s posture, under its own permission prompts.
- **Harness scores are not a leaderboard.** They are computed per harness precisely because harnesses differ in what they can express, so a gap between two columns is partly an observability difference and never a ranking. Fleet is the unweighted mean of the harnesses that scored the lane, not a fleet-wide truth, and codex-cli is under-represented in the archive by capture posture — the report says so where a blended number appears.
- **Scores never compare across lanes.** Each lane's constants are anchored on its own rules' thresholds, with no shared difficulty scale; "Session Hygiene 73, Prompt Quality 96" says nothing about which is going better.
- **100 means nothing this pack penalizes was observed**, not that the practice is perfect. The pack sees what the fold types, and that is five readings.
- The footer's rule-pack hash belongs with any number the user is going to quote elsewhere — a score without its stamp is comparable to nothing.
- The rest of the instrumentation footer is for coverage and performance questions; drop it from a polished coaching answer, and keep the citations and the stamp.
